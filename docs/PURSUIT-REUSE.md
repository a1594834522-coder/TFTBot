# 实时留牌计算复用

商店变化时，程序仍重新读取当前金币、实体持牌与对手。复用的是已声明条件下的数学中间量，而不是上一家店的建议表。

## 可复用的内容

- 相同目标副本、牌池占用和人口概率下的商店转移规律。
- 已准备完成并冻结的补齐/关键二星策略。完全展开的表可以服务它已经覆盖的后续副本与现金状态；只覆盖部分决策的表必须连有序购买起点和计算额度也完全相同，才能原样复用。不能把受限表的数值当成后续状态的最优价值。
- 相同模型和完整对手棋盘、权重条件下的棋盘加权数值。对手缺失概率继续保留，不能重新归一为全部已知。

策略签名包含目标顺序、已有副本、各目标剩余量、费用、购买价格、费用档总池、人口概率、目标集合、刷新价与英雄格数。现金和当前购买结果另由起点核对。任何不匹配都重新准备；新商店本身不被当作已知未来。

当前购买组合、支出、合法合成、装备、英雄形态、召唤物来源及落点部署每次重新验证。改变主线或目标会立即失效旧数字，旧任务仍按latest-only取消。尚未准备完成就被取消的策略不会写入策略缓存；已完成且冻结的数学子策略可以保留，不代表发布过期建议。

每个计算进程默认最多保留4份策略表，原转移缓存保留至多8个池、16个策略上下文，每个上下文至多16,384条转移行。标量评分沿用4个对手上下文和各16,384条数值的上限。缓存不保存推理张量或完整建议表。

诊断字段`adaptive[].reused`标记是否使用现有策略；`states`和`decisions`表示该策略原先准备的规模，不是这一次重复做了相同工作。模型落点评分额度保持384，未评分或未知质量不变。达标条件与最低剩余购牌费只随副本状态变化，也按状态复用；这不改变策略选择、搜索范围或额度。

## 可复现证据

`node --expose-gc scripts/audit-pursuit-workspace.mjs` 使用真实本地MetaTFT模型和合成固定局面。对照两边都使用同一模型实例及既有模型对局缓存，只有额外的留牌工作区不同。保持候选路线、持牌、牌池和对手，支付刷新费后改变当前商店。

| 情景 | 不复用留牌中间量 | 使用工作区 |
| --- | ---: | ---: |
| 再次比较同一40金局面 | 4.89秒 | 1.14秒 |
| 刷新后38金、新商店 | 4.15秒 | 3.05秒 |
| 再刷新后36金、新商店 | 3.55秒 | 0.91秒 |

三组对照均保留24种当前资产组合、各48个四/五英雄格情景、384个落点评估；完成概率、模型区间、余金、未知质量和组合保持数值一致（误差阈值`1e-8`）。38金时，旧五英雄格表曾触及额度，重新计算而未冒充可复用；完全解出后，36金的新起点才可复用。首次准备约5.53秒，未声称首次计算同步变快。

独立副本枚举测试核对降现金后续状态与新解一致；另检查受限表的起点/额度隔离、每个物理参数失效、取消、返回值防污染与缓存淘汰。集成测试改变商店位置、对手缺失质量与装备合成歧义，再与无工作区计算比较。

这些是单个合成工程对照，不是最坏延迟保证。实际玩家买牌、同行持牌、等级、价格或目标变化时可能不命中。真实连续游戏响应与排位收益仍待实局验证。

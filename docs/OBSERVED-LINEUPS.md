# MetaTFT 观测引导的混合棋盘

1.10.0扩展原有两牌联动搜索。它针对需要三、四张牌一起上场才成立的过渡和启动棋盘，也保留只换三张、继续使用强打工牌的方案。不是把用户自动切换到另一套阵容。

## 候选来自哪里

方向候选已有的MetaTFT前期、核心与主线高人口棋盘提供英雄共现模板。六人口及以下仅用实际前期关联，七人口同时考虑过渡与核心棋盘，八人口后可加入所选主线的后期变体。不会把不同棋盘的英雄并集当作真实观测。

新换上的实体必须来自同一个模板且确实在交易后的备战席上。已有商店购买由账本逐格收费、处理升星和装备归属；不存在或买不起的目标不会被插入。保留的原上场打工牌可以与终局零重合。模板用于生成候选，不用历史均名代替具体棋盘的战斗值。

每个模板分别探索三牌和四牌换下。候选的实际英雄、星级、形态、穿装、海克斯及已确认独立单位都进入原本的MetaTFT单场模型，使用同一对手集合与权重。每个实体只出现一次，装备不转移；装备明细未知或召唤来源限制不满足的候选被排除。

## 额度与含义

默认最多8个不同模板，每个模板96次候选生成，按可行的三/四牌情景分配额度，每模板最多512次检查。模板身份、核心优先级与实际星级只决定探索顺序，最终由战斗模型排序。原有两牌邻域与真实不动棋盘始终保留。达到额度时在计算依据中说明；这不是穷举所有四牌替换或全队最优。

当前补强先比较同样搜索范围里的不购买方案，已有免费重组收益不能计给买牌。预算落点的当前参考和每个未来落点也使用同一范围。装备承接同时扩展部署，并重放当前换牌已找到的无出售方案作为基线下限：核对真实动作、实体和现金，重新评分，而非引用旧胜率数字。未知对手质量仍保留上下界，三类模块的收益不能相加。

未来刷牌仍采用明确的参考购买策略，未建立任意自适应摇摆或未来接装优化。当前接装仍最多出售两名非核心持装者；全队换下、装备分配与模型棋盘都各有限额。模型不含站位或长期名次收益。

## 验证

- 独立小棋盘全组合对照：三张联合改善而单换均变弱；目标未出现/买不起；保留强带装打工牌优于四张全换。
- 免费重组先于购买收益；装备承接重放已知更强的无出售参考，并拒绝过期实体、错误余额或偷偷出售的引用。
- 三/四牌和不同模板分别分配额度；形态、星级、装备及召唤来源守恒；未知对手与装备不伪装成已知。
- 零预算未齐落点与当前免费重组使用同一范围，避免把部署范围差异当作刷牌风险。
- `node scripts/audit-observed-lineups.mjs`：明确的合成原生契约、实际观测模板、真实本地模型。提供共用缓存和独立缓存的耗时，不能当成最坏性能或真实对局收益保证。
- worker和私有原生通道可复现：`npm run test:direction:worker`；`$env:TFTBOT_TEST_MIXED='1'; npm run test:recognition:native -- --headless`。原生测试先验证旧链路，再切到新的合成持牌，核对四牌换上/换下、桌面明细和主线保持。

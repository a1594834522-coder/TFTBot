# 搜牌预算落点

1.7.0 将“是否凑齐核心”与“搜完留下什么棋盘”分开比较。桌面阵容助手在启动阶段、七人口以上、玩家已手选主线且全场持牌可计算时，展示主线优先及最多两个同玩法备选的兼留情景。不会自动选择或改变主线，也不会发送游戏操作。

## 策略与分布

`search-distribution.ts` 使用现有有限牌池转移核：费用独立抽取，同费实体在同一商店内无放回，未买的牌在下一次刷新前归池，已买的牌从后续牌池移除。逐次支付刷新和购买费用，不虚构未来收入、升级或出售回收。当前已见商店先处理，只付购买费，不重复收刷新费。

每个情景声明目标副本数与可完成的核心组合。已揭示商店里，优先购买能在该商店完成下一次常规升星的目标，其次接近升星的目标，再按主线/备选声明顺序购买。兼留情景在任一双核达到目标副本数时停止；否则继续到钱包无法刷新。决策只依赖已持与当前已揭示商店，没有预知未来来牌。这是明确的参考策略，不是全局最优搜牌策略。

主线赌狗目标为主核9张及前排3张，84/95为各自双核3张；兼留仅比较同玩法候选，玩家仍可自行切换主线。当前预算落点入口限启动与后期，前期赌狗继续使用既有追牌参考；不能宣称已覆盖早期所有留牌决策。主线核心已齐时，停止展示重复追牌情景，转去现有换牌/上限参考。

按剩余现金降序合并相同持牌状态，保留成功与未齐的全部终止分支。默认每个情景最多展开1500个状态；未展开质量保留为未知，不对已知分支重新归一化。4和5英雄格分别计算，界面切换查看；没有把实际仙灵周期假装成固定格数，也没有把两个情景称为置信区间。

## 将部分进展还原为棋盘

`search-landings.ts` 从每个终止分支的新增副本重建物理持牌。重建与实际购买共用升星/装备合并规则，但不产生交易指令或假设现金；金钱由分布单独核算。原穿戴物品保持其实体归属。来源不明确的未来形态、未覆盖的合并/装备规则、需要另行整理的备战席，不冒充已验证棋盘。

在相同当前对手集合和权重下，比较这些落点的合法部署。1.10.0当前参考和未来落点均使用基础两牌联动与MetaTFT观测引导的限量三/四牌重组；不出售打工牌，不转移装备，不优化站位。固定对手棋盘只是可比条件，不代表未来对手不会变强。基线使用当前持牌能免费换出的最好已搜索棋盘，不是原样不动的棋盘。

展示：全部落点加权的模型胜率参考、核心目标未齐概率、低于基线的概率，以及目标未齐条件下的平均模型参考。展开时展示一个具体未齐落点及其概率。某个未齐落点可能仍然很强，不能赋值为0；升星合并也可能在模型中变弱，不能一律判为提升。

每个方案最多新评估96种副本组合，共享缓存但各有独立额度。未评估棋盘及未确认规则保留原质量和[0,1]战斗值界；缺失对手也保留其未知权重。若核心未齐事件本身还有未展开质量，条件平均值同样保留上下界，不除以“已知的失败样本数”假装完整。区间表达未知输入/计算覆盖，不是排位胜率的统计置信区间。

## 验证与边界

- `tests/search-distribution.test.ts` 使用独立实体牌堆递归核对整个落点分布、购买/刷新现金、无放回多槽抽牌和失败分支。固定目标成功率另与已有完成概率核对。
- `tests/search-landings.test.ts` 覆盖未齐但已提升的带装棋盘、未知对手质量、未评估质量、合并导致变弱、手选主线、三种玩法分离、已成型后停止重复追牌及桌面文案。
- `scripts/audit-search-landings.mjs` 使用明确合成的原生契约事件、实际主线/前期关联、完整物理牌池和真实MetaTFT本地模型。当前40金例子约1.6秒，部分兼留组合战斗评估覆盖约98.2%；没有把剩余质量当作0或重新归一化。此耗时不是最坏情况性能保证。
- 独立计算进程和原生桌面联调验证实际接口与交互，不能代替整局实战校准。

此功能已让失败分支参与比较，但尚未完成任意多副本自适应摇摆、卖牌接装、大幅整体变阵、未来对手变化或长期名次收益优化。历史关联用于给出可比较的候选，不能据此宣称兼留某分支必然提高上分率。

1.10.0会重新计算同一部署范围下的免费参考，不把当前能做的三四牌换队收益算给未来搜牌。观察模板只生成实际持有英雄的混合候选，不强制完整套用历史棋盘；仍不含未来接装与任意全队最优搜索。

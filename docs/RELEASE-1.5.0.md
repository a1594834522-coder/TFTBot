# TFTBot 1.5.0

修正召唤单位和英雄形态对战斗参考与换牌比较的影响。

- 对齐用户提供的 MetaTFT 原始 live-board 编码：28 个已核实、未独立编码的非商店单位不再让整场计算失败，保留“未单独建模”标记。未知新英雄仍不能被静默丢弃。
- 修复缓存编码读取原始位置而非压缩后位置的问题；召唤物穿插在英雄之间或原始数量超过14时，完整推理与缓存推理保持一致。
- 已确认来源的巨塔/训练假人随候选棋盘保留，装备不会消失，也不进入普通持牌买卖账本。
- 已观测的伙伴近战召唤物，在约德尔人和朋友羁绊已激活、相应海克斯已确认，且来源实体、星级和装备保持不变时参与比较；可继续比较其它英雄的替换。
- 拉克丝9种已知形态保留自己的战斗羁绊，共用同一牌库身份。形态从原生商店/棋盘进入交易状态、合成和候选棋盘；不同已知形态不会借用旧侦察装备。形态中文名放在悬停详情中。
- 新增战斗单位策略的源文件/lookup/非商店表哈希、完整覆盖与来源描述联检，避免换模型后继续套旧规则。

边界：此模型没有召唤物的完整动态属性输入，Dummify历史属性、基础拉克丝尚未确认的形态会作标记。来源未核实的独立单位仍暂停换牌比较；本轮没有猜测魔像来源。伙伴具体骑乘者尚未经过真实对局核验，当前保护全部相关实体及装备，尚不比较更换骑乘者后的新召唤物。统计阵容家族的形态细分、完整变阵及卖牌装备承接仍待完善。

原始编码对照：50种情况、355,700个数值，最大误差约5.96e-9。脚本 `scripts/audit-model-encoder.mjs` 只执行哈希固定的已检查纯编码函数，不启动原应用。REA证据、提取函数和报告保留在忽略的 `dist/model-encoder-audit/`，原始程序不提交仓库。

581个测试、类型检查、构建通过。最终打包程序通过普通和召唤物两种原生通道联调，包括持牌双视图、中文保留说明、主线/过渡同步、浮窗、仙灵与海克斯评级；六种独立计算进程场景通过。未运行真实游戏，尚未验证整局表现或排位收益。

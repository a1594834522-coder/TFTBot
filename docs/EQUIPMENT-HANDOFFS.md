# 带装打工牌的装备承接

1.8.0 在玩家手选主线后，比较保留现有牌与出售持装英雄、购买当前可见核心、再接装上场的方案。只展示数据与具体变化，不执行出售、购买、装备或摆位。

## 数据与实体

`data/equipment-rules.json` 来自用户提供的 `TFTSet18_latest_en_us.json`：149个装备条目、181个英雄身份的原生羁绊，保留配方、数据中声明的唯一性、关联/冲突羁绊与装备标签。源文件SHA256及PBE元数据随快照保存。构建时核对赛季、全部普通商店英雄、已有装备配方、改变出售规则的海克斯描述，并把规则纳入决策数据清单。

运行时不读取外部原程序。更新参考文件后，可设置 `METATFT_REFERENCE_DIR` 并运行 `node scripts/build-equipment-rules.mjs`。规则仍是标明的S18 PBE参考，不能当作正式服全部机制已核验。

每件装备都有独立token。出售把原token送回装备栏，接装从装备栏移出同一token；不会复制装备或移走仍留在其它英雄上的装备。两散件合成必须同时消耗实际材料，记录新物品与两个来源。允许先合成再放第三件；按不同放置顺序生成候选，装备栏排列顺序不会强制决定配方。

临时装备、药剂、选择器、窃贼手套及人口装备的额外机制未纳入普通接装。这些装备不能被当成普通返还物品，且含此类装备的英雄不作为普通出售来源。未知穿戴不视为空。已有核心的装备保持绑定；可分配对象是实际持有或当前商店买到的核心实体，最多四个实体。

## 对照与范围

先评估不出售时的当前核心购买、装备栏分配和合法上场，求出已比较的无出售基线。随后比较最多两名非核心持装英雄的出售组合；每个被卖英雄都必须贡献到实际接装，不能夹带纯换现金的额外出售。当前商店之外的英雄不会被虚构为已买到。

出售返款与购买费用分别记账，展示具体回收、花费与余额。不购买主线以外的英雄，不出售已选双核。每个结果最多让两名原上场实体离场；原装备、核心星级、失去的单位与羁绊都进入同一对手分布下的模型比较。召唤者/装备绑定等已建立的独立单位约束继续生效。

装备分配按MetaTFT的同家族/英雄装备兼容频率组织限量候选，保留不分配、完整集中分配和不同槽位使用的方案；最终按真实本地战斗模型比较。默认24个分配候选、最多12个出售组合、16000个模型棋盘；这些是候选搜索限制，不是穷举所有装备与变阵。所有模型比较保留缺失对手的未知权重。

如果没有接装方案优于已比较的无出售基线，仅展示一个如实的对照，不用额外现金推动大幅掉战力的方案，也不宣称主线一星必然强于两星打工牌。这仍没有给保留打工牌的长期选择价值定价。

## 需要明确的条件

- 已选海克斯与装备栏必须同步。海克斯未知时不能假设普通出售；“坚守阵容”和“打捞桶”两种版本的规则由源描述明确识别，普通承接不适用。
- 装备栏容量目前未实测确认。此时显示“装备栏需空N格”，结果以这个空间条件为前提，不声称已验证可以直接出售。已知容量不足的方案不会被当作直接可执行。
- 模型不含站位、永久叠层历史、装备栏触发的额外战斗属性或其它未建模特殊机制。预测提升是同一当前对手条件下的模型差值，不是实局保证或最终名次收益。
- 预算落点1.7.0仍按原穿装备比较；本轮接装没有悄悄混入其平均值，也没有解决任意未来搜牌后的接装策略。

## 验证

单测覆盖返款购买、装备实体、无需出售的装备分配基线、负收益、未知对手质量、召唤来源保护、散件顺序、满三槽合成、唯一性/羁绊限制与只读界面。

`node scripts/audit-equipment-handoffs.mjs` 使用明确的合成原生事件与真实本地MetaTFT模型。本次例子比较112个棋盘约118ms；无出售基线约73.2%，两个接装方案分别增加约18.7/17.6个百分点，均保留装备格条件。不是实战结果或最坏情况性能保证。

原生桌面验证：`$env:TFTBOT_TEST_HANDOFF='1'; npm run test:recognition:native -- --headless`。所有输入走独立私有通道，不连接真实游戏。

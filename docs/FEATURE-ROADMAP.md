# 数据驱动的云顶助手路线

当前方向（1.2.0）：以用户手选阵容为主线，提供过渡、变阵和上限参考。自动定阵与游戏自动操作不属于当前交付目标；下方其它能力是探索清单，不代表已经实现。详见 [体验设计](COMPANION-EXPERIENCE.md)。

当前交付：独立 TypeScript / Vue 桌面程序，参考阿木木的顶部导航、左侧资料库和可展开阵容卡片。MetaTFT 为默认主数据源，官网与 Blitz 可显式切换作对照；只发布最新赛季 S18。英雄、装备、羁绊和海克斯采用 MetaTFT 中文名称表，海克斯评级使用 `augments_tiers` 作者 S–D 榜单，支持本地快照、缓存与刷新。

阵容推荐与主线辅助的候选池、装备适配、过渡棋盘、升级节点、海克斯关联和站位数据均来自 MetaTFT。决策输入必须保留赛季、版本、抓取时间、样本量与来源；其它数据源不自动参与决策打分。MetaTFT 不可用时保留同赛季缓存并提示数据时间。

中文表来自 `https://data.metatft.com/lookups/TFTSet18_latest_zh_cn.json`，仅提取名称及 ID 别名，不引入其中的 PBE 数值。该表有一条英文名称、两条评级 ID 缺失，分别补为“挑战者的恩典”“致命丽花+”“好事成双”；元数据记录了这三项人工覆盖。新 ID 缺中文名时显示“名称待更新”，不猜测旧赛季名称。中文官方名称中的罗马数字和“DD街区”等名称原样保留。

## 优先实现的决策能力

| 功能 | 数据与输入 | 有用的输出 | 主要限制 |
| --- | --- | --- | --- |
| 阵容导航与转型 | 当前英雄/装备、comps/options/builds、已知同行 | 保留哪些牌、装备适配、两条转型路线及理由 | 必须有可靠当前状态；不能把静态排行直接当本局最优 |
| 三选一海克斯建议 | augments_tiers 作者评级、comp_details.augments、当前阵容与阶段 | 基础评级、阵容适配、收益条件 | 作者评级不是胜率；联合统计接口可能忽略筛选，不编造组合胜率 |
| 经济和升级教练 | levels/final_levels、shopOdds/expPerLevel、金币/等级/连胜/血量 | 存钱、升级、搜牌建议及机会成本 | 等级与名次相关不代表因果，保留风险解释 |
| 搜牌预算估算 | shopOdds/shopPool/unitCost、已知占牌、目标副本 | 预算内命中率区间、停手条件 | 未观测占牌需估算，不能伪装精确剩余牌池 |
| 对位与站位建议 | positioning/relative_positioning/counters、可靠棋盘 | 可视化站位热区、前排/后排调整建议 | 热门站位不等于针对当前对手的最优站位 |
| 自动复盘 | JSONL、每回合状态与决策 | 关键转折、经济损失、漏买/过度刷新等候选问题 | 将可观测事实和推测分开记录 |

## 采集与辅助闭环

1. **状态采集**：优先接入原版 GEP 原生事件链路。已实现原版后台启动、当前云顶检测规则登记、overlay/GEP 加载请求、独立原生 IPC 子进程和商店/海克斯面板。实际服务握手与合成协议到界面均已通过；真实游戏中的插件加载、持续读数和玩家英雄/棋盘完整接入仍待验收。OCR 仅作为缺失字段或采集失败时的备选方案。未知 ID、槽位不完整或状态过期时不执行自动动作。
2. **决策器**：纯 TS 输入快照和策略，输出买牌、刷新、升级、摆位的计划及理由。记录预算、动作前置条件和策略版本，以同一批录像回归。
3. **确认执行**：先显示建议并由用户确认；从单步开始，读取动作后的截图验证金币、棋子和位置确实变化。
4. **完整自动流程**：再处理准备阶段、商店、备战席、合成装备、选秀和海克斯；提供随时暂停与预算上限，避免重复点击和失控刷新。

完整自动对局需要额外实现可靠的状态识别与执行层。MetaTFT 提供的统计数据不能替代本局商店、金币、棋盘或玩家行为，不能据此保证上分。当前版本不执行自动买牌、刷新或摆位。

接口依据：用户提供的 `metatft/INTERFACES.md`，其中 `augments_tiers` 明确是人工评级，explorer 的单位/装备/海克斯联合筛选可能被忽略。当前实现不依赖 MetaTFT 的 GEP 或注入其应用。

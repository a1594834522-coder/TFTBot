# 留牌与定阵：跨阶段决策算法

状态：设计与数据基础已落地；桌面当前仍使用明确标注的规则原型。本文不是已验证的上分承诺。

## 1. 决策对象是路线和行动，不是终局阵容相似度

例子：2 阶段的强势打工队可以与最终阵容零重合。它的价值来自保血、连胜、经济、装备携带效率以及之后换队的成功率。终局牌买得过早反而可能占格、卡利息、削弱当前战力。

因此同时处理三个时间尺度：

- 眼前：这家商店买哪些、卖哪些，怎么上场和穿装备，是否影响下一档利息。
- 数回合：用什么棋盘过渡，什么时候升级或搜牌，什么条件下换队。
- 终局：哪些阵容及其具体变体仍可达，预期名次分布怎样，失败时如何止损。

“共同英雄”只用于计算资产继承与换队成本，绝不作为转型边存在与否的判据。尚未定阵时保留的是有价值的选择权，不是每条路线各囤一份牌。

## 2. 本次实际取到的数据

当前聚类 `2745`，`TFTSet18`。脚本读取官方前端实际调用的：

```
https://api.metatft.com/tft-early-comps/comps_overview
https://api.metatft.com/tft-early-comps/comps_full?stage=2&cluster_id=0&clustering_id=2745
```

`forwards_links` 未显式说明版本切片；本项目不把它与当前版本条件权重当成同一个量。多阶段探索使用当前条件表的权重，分母包括被剪枝边和退出项。

统计权重有小数，来源可能含软聚类或重复观测。它不是独立对局数，不能直接拿去构造二项分布置信区间。公开的聚合表包含不同粒度与条件方向，必须在每个特征上保留来源、时间窗、分母和可用性。

一个实际例子（该快照）：

```
3 阶段：阿卡丽 / 卡蜜尔 / 蕾欧娜 / 慎
   ↓ 有真实条件统计，英雄零重合
4 阶段：阿木木 / 厄斐琉斯 / 黛安娜 / 克格莫 /
        奈德丽 / 苍蓝雕纹魔像 / 韦鲁斯 / 蔚
```

这条边的当前版本条件均名约 `3.91`，权重约 `117.57`。它证明这种转型确实存在于统计中；它不能证明任何经济、血量、装备的玩家都应这样转，也不证明这是最优路线。

## 3. 状态表示：实际资产与未知部分分开

`S = (回合、等级/经验、金币、血量、连胜败、棋盘、备战席、装备栏、海克斯、仙灵、商店、全场持牌、历史)`。

棋子按实体记录 ID、星级、格子、装备和是否可移动；同时保留实体与基础牌张数的关系。装备使用唯一 token：不能把同一个羊刀同时算给打工牌和终局主 C。必须模拟出售、转移、合成和特殊拆装条件。

每项输入都有时间戳和可信度。未知金币不是 0，缺失对手不是空牌库，未知散件不是没有散件。读取器已经观察到金币与装备栏事件，但当前原型没有完整解析它们；必须补齐实际报文契约再开放预算建议。经济不完整时只给路线参考，不能输出“买这三张仍有利息”这样的伪精确建议。

全场持牌既用于有限牌池，也用于推断同行下一步需求。对手意图以多种可能路线的分布表示，并随其购买/出售记录更新，不能仅凭一张通用前排就认定同行。

## 4. 两种图必须分开

### 4.1 经验转型图

节点是阶段棋盘簇，边是实际观测关联，允许零英雄重合。星级、装备携带者、人口、回合、具体变体是节点附近的证据层。

图负责提出候选，不负责直接替玩家决策。常见路线不一定强，强路线不一定买得起；低频路线也不能只因低频被永久排除。候选生成同时保留常见路线、结果较好的路线、当前资产可达路线，以及必要的保命路线。

多跳的 `Σ/Π` 组合只能视作一阶 Markov 近似；不能声称从 A→B 和 B→C 的统计已得到 A→B→C 的联合最终胜率。更长历史、装备、经济可能改变转型结果；需要条件统计或经验证的预测模型补充。

### 4.2 可执行行动图

节点是本局具体状态，边是合法操作与环境随机结果。买牌、卖牌、经验购买、刷新、换上场棋子、合装和装备转移都必须满足真实规则。

经验图给出“可以考虑换到什么”；行动图回答“从当前状态怎么做到、代价多少、最坏会怎样”。它们不是同一组转移概率。

终局阵容聚类和前期棋盘聚类是两套 ID 空间。先用详情里的早期棋盘、具体终局变体、星级与羁绊建立跨表描述；精确同棋盘可建立身份映射，近似匹配保留候选和误差。相似度映射只叫映射，不能伪装成实际观测的转型边。继续审计官方筛选、聚类详情及条件接口，优先寻找直接的跨表关联。

## 5. 优化目标与估值

最终目标采用排名奖励 `R(rank)` 的期望；配置可信 LP 表时优化期望 LP，没有时以 `-rank` 为明确的替代目标。不能仅由均名倒推出前四率、吃鸡率或完整名次分布。

有限时域滚动规划：

```
Q_h(S,a) = E[当步真实奖励 + V_(h-1)(S') | S,a]
V_h(S)   = max_{a ∈ Legal(S)} Q_h(S,a)
```

正常回合金币与血量属于状态，不直接凭手工权重加到“阵容强度分”里。通过未来可执行行动、战斗和终局价值体现它们的价值，避免保血、强度和均名被重复计分。地平线末端由校准过的状态价值模型估值；没有可靠模型的区间要报告敏感性和比较的不确定性。

用滚动时域约束计算量：眼前商店精确枚举购买子集及必要出售；未来若干回合模拟刷新、自然来牌、升级、对手占牌和战斗。跨阶段路线作为宏行动提出，具体换队时机仍由预算和战力决定。每次新商店、新装备、新海克斯或对手明显变化后重算。

策略收益过于接近时保留当前路线，使用切换成本和配对模拟误差判断是否值得换；不要固定“分差 4 分就不换”的任意阈值。

## 6. 留牌是反事实边际价值

对当前商店或备战席的一张实体牌 `c`，比较两组最优合法策略：允许保留/购买它，以及禁止保留/购买它：

```
Δ(c | S) = max_π E[R | S, 允许 c] - max_π E[R | S, 禁止 c]
```

这是研究口径，不是把两条历史均名相减当成因果效果。实际估计由受约束模拟、条件预测和回放验证提供。

逐牌独立的 Δ 不能直接变成推荐列表：三个对子可能各自值得留，却不能共同占用同一笔金币和同一格备战席。最终输出的是**一个整体可执行的留牌组合**：

1. 枚举最多五个商店位置的购买子集，重复英雄按实体与即时合成处理。
2. 对每个子集生成可行出售/保留方案，保护装备、在场战力、重要对子；允许卖掉沉没成本牌。
3. 精确结算买卖金币、合成、备战席容量和回合结算利息；刷新不返还已购买的金币。
4. 对可行组合展开多条过渡和转型策略，比较其终局价值；对子、打工牌、未来主 C 在同一个资源账本里竞争。
5. 选中整体方案后，再用移除某张牌的配对比较生成“立即升星”“稳住当前棋盘”“保留转型入口”等短理由。

一张最终会卖掉的打工牌，只要带来的保血/经济和装备效率超过占用成本，就可以比终局体系牌更值得买。反过来，不能因为当前持有二星就无条件保留：两星会占场上位置，出售可能释放装备和转换预算。

## 7. 定阵是可达性与机会成本的比较

候选不是每个大阵容只取最常见的一套八人口截图，而是其不同人口、主副 C、替代前排、星级目标、出装分配和特殊羁绊条件下的变体。

对每个候选策略同时估计：

- 到达关键战力节点的概率、所需金币分布和到达回合，而非只估“下一张”的均价。
- 为此暂存的牌会损失多少利息、格子和当前战力。
- 现有装备能否在过渡期发挥作用，何时能合法转移，是否必须牺牲重要二星。
- 失败分支：没找到主 C、前排没二星、被同行拿走关键牌时的可用替代路线。
- 最终名次分布及尾部风险。血量低时，不可把只有少数天胡能达成的高上限当主要建议。

保持 2–3 条可执行备选，但不要奖励“路线越多越好”的抽象多样性。选择权的价值应该来自不同未来商店和装备结果下可以改走更优策略，即 `E[max V]` 的增益，而不是简单的路线数量或熵。

明确区分用户主动锁定、软推荐和自动跟随。默认不会擅自改掉用户选择的阵容；强锁只在用户明确要求时作为约束，否则仍可提示更划算的转型。

## 8. 世界模型与统计学习

### 8.1 商店与经济

使用当前赛季经核验的等级概率、各费用池容量、英雄剩余牌量和特殊规则，模拟五位置抽样与牌池回收。自己的牌、对手的牌、当前商店、购买、卖出、淘汰回流都进入同一账本。多人共用牌池使目标之间相关，不能把每个目标的独立均价直接相加。

对手读取不完整时使用多个合理牌池情景，报告决策在这些情景下是否稳定；不把“缺失”当作“仍全在池里”。仙灵按真实刷新/回合状态单独建模，不能占用一个普通英雄抽样位置而仍假设五张常规商店。

金币、利息、自然经验、升级阈值、刷新券、特殊经济海克斯和仙灵都从规则表或已核验事件驱动。不能用错误的经济模型给正确的战斗模型配预算。

### 8.2 战斗与短期保血

MetaTFT 官方模型提供一个起点，复现其单位 one-hot、角色、星级 `/4`、费用 `/5`、最多三件装备编码、羁绊去重和阈值、海克斯标签以及空位填充。

本次核实官方代码以每方最多 14 个单位构建输入；已有模型文件有 146 个命名输入、5 个输出，不是直接喂一个 346 维表就能调用。`lookup.num_features=346` 是编码描述，不能误认作模型唯一输入维度。官方胜负输出取第 5 项，前两项有强度线性缩放；强度分位表与这些输出的标尺不可混用。

模型与 lookup 需作为一个版本组合校验：输入名、维度、编码边界、赛季、哈希以及最后修改时间。先验证交换双方是否近似互补、同阵镜像、升星、装备替换的合理性，再用同版本实际战斗日志检查校准。未验证前仅作研究特征，不宣传为本局胜率。

阵型、站位、海克斯和仙灵效果可能超出模型表示能力。保留相应不确定性；不能因一个手工 S 评级就给整队固定加成。失血还取决于回合和存活单位，单有胜负概率不足以预测血量。

### 8.3 长期价值和转型学习

首先以条件转型表建立经验先验，结合人口、星级、装备与经济可达性生成候选。随后训练分层状态价值/结果分布模型，按补丁、阶段、经济区间、装备角色、星级、海克斯、同行等条件逐步细化；联合条件必须来自真实联合统计或可复现的样本。

探测接口时记录过滤前后的分母和结果差异。重新核对官方客户端后已证明，之前 `units=` 等参数错误；使用真实的 `unit_unique`、`item_unique` 后联合筛选有效。详见 `METATFT-CONDITIONS-AUDIT.md`。后续条件也必须逐类验证作用域，不能混淆“全队拥有某装备”与“指定单位携带某装备”，更不能把终局条件表当行动因果收益。

避免三个偏差：

- 存活偏差：能九级的玩家往往本来就经济/血量更好，九级均名更好不等于现在升九一定赚。
- 反向条件：`early_options` 是在某终局簇内看的前期分布，不能直接当 `P(终局 | 前期)`。需要统一样本空间的分母、先验与未覆盖类别。
- 相关观测：同一玩家跨回合、跨软簇出现，不能把所有权重当独立样本叠加。

若后续使用有限样本回放辅助学习，应按需求、分层、去重并遵循数据可得范围取样；线上 HUD 只消费压缩聚合与模型，不下载所有历史对局。训练数据和线上特征必须以决策时可见的信息为准，禁止把最终阵容、最终排名泄露为当时输入。

## 9. 搜索实现与计算预算

候选生成、世界模拟、价值估计分层实现，允许分别替换与校准。先对眼前商店做小规模精确搜索，再用 beam search / 场景采样扩展后续策略；图上的路线频率仅作提案先验，不做硬约束。

所有候选共用同批随机商店、装备与对手情景做配对比较，减少模拟噪声。对接近的前两名追加计算，优势明显时提前停止。误差条区分“有限模拟误差”和“模型对真实游戏的误差”；前者很小不能证明后者很小。

给保命行动、低频强路线、主要出装与替代前排保留 beam 配额，避免仅按常见路线剪枝。缓存键覆盖阶段、金币、经验、实体持牌、装备、海克斯、仙灵、商店和对手状态，任何影响可执行性的变化均使旧结果失效。

目标预算：常规商店变化先在 200ms 级给出已确认的合法变化，复杂搜索在后台增量计算；具体预算需实测，不作为当前性能声明。新状态到来取消旧搜索，HUD 不展示过期建议。大型研究数据不打入渲染器或每次 IPC 传输。

## 10. 评估与上线门槛

基础约束先通过：不超预算、不超格、不重复使用装备、不购买不存在的商店位置、不丢失卖出和合成回流、不让已结束对局继续推荐。只有经济状态完整且规则核验通过，才开放具体买卖/刷新预算建议。

对照至少包括当前规则原型、只追终局重合、只看早期胜率、仅经济策略，以及去掉转型图/装备转移/同行/血量的消融版本。必须有“零终局重合的优质打工”“少一金币卡利息”“备战席最后一格”“装备只能卖出转移”“低血量买不起高上限”“多个对子竞争金币”等反例。

时间上用较早窗口训练、较晚窗口验证，按对局/玩家分组避免跨回合泄露。补丁切换单独测，不能随机拆行后声称泛化。评价看名次/LP、血量轨迹、经济轨迹、关键升级到达时间、无效换队、建议抖动、可执行率和校准误差。

只有聚合数据时不能做严格的逐操作离线策略价值评估，也不能凭条件均名宣称策略因果提升。回放环境也会有模型偏差，必须保留影子模式真实对局验证：只记录建议与结果，不自动操作。策略评估需要记录玩家实际行动；单纯“玩家没照做”不能直接当推荐失败或成功。

发布要求依次为：数据与规则契约通过 → 模拟器约束与守恒通过 → 反例与回放对照通过 → 影子模式校准通过 → 小范围提示。若要宣传提升期望排名，需要有足够的前瞻性对照证据。
